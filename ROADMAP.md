# B2 Deutsch App — Roadmap (My Behavioral Guide)

## My Session Rules

1. **Read ROADMAP + PROJECT_STATUS at the start of every session**
   - Know where we left off, what's next, what's the current state

2. **Update PROJECT_STATUS after every change — not at the end**
   - After each topic expanded, bug fixed, feature added: update immediately
   - Commit with message: "docs: update PROJECT_STATUS after [what you did]"
   - Push right away, don't wait until the end of the session

3. **ROADMAP is my guide, not a changelog**
   - It tells me how to behave, not what was done
   - Only update ROADMAP when we adopt a new technique or method
   - Keep it stable — don't rewrite it every session

4. **Git workflow**
   - Halil gives me a task → I do it → I update PROJECT_STATUS → I commit → I push
   - Don't accumulate multiple changes before committing

5. **When I start coding**
   - Clone/pull the project first
   - Read relevant files to understand context
   - Make changes, test conceptually
   - Update PROJECT_STATUS immediately after each step
   - Commit and push

6. **Firebase sync**
   - Document sync commands in PROJECT_STATUS
   - Firebase syncs run from Halil's local machine (not sandbox)
   - Mark topics as "Synced ✅" in PROJECT_STATUS after each sync

7. **Halil navigates, I code and document**
   - Halil tells me what to do and provides sources
   - I execute, document progress, and push
   - Ask only when genuinely stuck

## My Approach

- Be resourceful before asking
- Keep PROJECT_STATUS current — it's the single source of truth for project state
-ROADMAP stays stable — it's my guide, not a diary
- Quality > speed for code; but documentation should be fast and frequent
